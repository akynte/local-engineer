# Task-success results — 2026-09-14

`le eval run` over 3 tasks × 4 arms, 5 passes, 60 runs, against a local model on the hardware below.

## The short version

**No comparison in this run is statistically detectable.** Every arm's confidence
interval overlaps every other's. The numbers below are worth publishing because
they are real and reproducible, not because they settle anything.

What the run does establish:

- The harness executes end to end against a local model, and the completion
  contract accepts and rejects on evidence it actually gathered.
- False acceptance is real and measurable: the unsupervised baseline claimed
  success on work that failed the hidden test in 4 of 15 runs.
- 4 of 12 task/arm cells changed verdict between passes.
  A cell that disagrees with itself has not been measured.

every solved rate, never folded into it.

## What the comparisons say

**Does the harness beat the same model driven directly?**

- `unsupervised`: 73% [48–89%] (11/15)
- `supervised`: 93% [70–99%] (14/15)
- Isolates the whole pipeline: retrieval, the graph, and the verification loop together.
- **no detectable difference (20-point gap, intervals overlap; this set is too small to tell)**

**Does the code graph contribute anything beyond lexical search?**

- `supervised-no-graph`: 93% [70–99%] (14/15)
- `supervised`: 93% [70–99%] (14/15)
- Isolates graph expansion and impact analysis, with everything else held constant.
- **no detectable difference (0-point gap, intervals overlap; this set is too small to tell)**

**Does the verification loop contribute?**

- `supervised-no-verification`: 93% [70–99%] (14/15)
- `supervised`: 93% [70–99%] (14/15)
- Isolates the compiler-and-test correction signal, with everything else held constant.
- **no detectable difference (0-point gap, intervals overlap; this set is too small to tell)**

## Cost, and the one task that discriminates

Two of the three tasks were solved by every arm on every pass, including the
baseline with no retrieval, no graph and no verification. They are at ceiling and
carry no information about the arms. Everything below comes from the third.

| Arm | `signature-change-001` solved | False accept | Median tokens on it |
|---|---|---|---|
| `unsupervised` | 1/5 | 4/5 | 27,759 |
| `supervised` | 4/5 | 1/5 | 47,191 |
| `supervised-no-graph` | 4/5 | 1/5 | 24,277 |
| `supervised-no-verification` | 4/5 | 1/5 | 38,206 |

Three things follow, none of them statistically established, all of them worth
a larger task set to check:

- **The whole solve-rate difference lives in one task.** The baseline solved it
  once in five and false-accepted the other four times; every supervised arm
  solved it four times in five. A three-task set with two at ceiling is not
  measuring the pipeline, it is measuring one fixture.
- **The graph earns nothing here and costs a great deal.** Removing it changed
  the solved rate by zero points and roughly halved the tokens spent on the only
  task that discriminates. On fixtures this small, lexical retrieval already
  surfaces what graph expansion would find, and the expansion is pure overhead.
- **The verification loop pays for itself in tokens**, not in solve rate:
  same 14/15, but the arm without it spent about a third more tokens overall.
  Correction from a compiler is cheaper than correction from re-reading.

## How to read these numbers

- 4 of 12 task/arm cells changed verdict between passes. The set was run 5 times; a cell that disagrees with itself is not evidence about an arm, and comparisons drawn across arms are weaker than the intervals alone suggest.
- The task set has 3 tasks. Confidence intervals at this size are wide enough that only large differences are detectable; treat every rate as indicative.
- unsupervised claimed success and was wrong on 4 run(s) (27% [11–52%] (4/15)). A solved rate should never be read without this number beside it.
- supervised claimed success and was wrong on 1 run(s) (7% [1–30%] (1/15)). A solved rate should never be read without this number beside it.
- supervised-no-graph claimed success and was wrong on 1 run(s) (7% [1–30%] (1/15)). A solved rate should never be read without this number beside it.
- supervised-no-verification claimed success and was wrong on 1 run(s) (7% [1–30%] (1/15)). A solved rate should never be read without this number beside it.
- Acceptance files are never in the worktree while a task runs, so no result
  here can come from a model reading the test it had to satisfy.
- Intervals are Wilson intervals. Arms whose intervals overlap have **not**
  been shown to differ.

## Reproducing

```console
$ le models bench --write
$ le eval run \
    --arms unsupervised,supervised,supervised-no-graph,supervised-no-verification \
    --repeat 5 --out results.json
$ le eval report results.json
```
